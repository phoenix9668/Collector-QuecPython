# 4.1.5 凭证修复与审查报告

审查日期：2026-11-14。基线：4.1.4 / `7a0f127`。范围：MQTT认证、凭证读写、身份迁移、启动恢复、OTA回滚和空间预算，并复核队列、日志、UART和传感器的相关调用。

## 故障判断

4.1.4将任意连续三次连接异常解释为动态密钥失效，删除缓存并强制重新注册。超时和订阅失败也进入该分支。故障设备先前在线，后来配置密钥和缓存密钥均为空、ProductSecret仍存在，符合这条故障链。现有现场日志不足以还原最初三次失败的具体原因。

阿里云说明，已激活设备需要重置动态注册状态才能再次动态注册。因而短暂网络异常可以经上述代码变成持续认证失败。设备本次经人工处理恢复连接，不代表这个触发条件消失。[阿里云动态注册说明](https://help.aliyun.com/zh/iot/developer-reference/overview-37)

UART解析计数是另一条数据通路；本次修复没有把串口计数当作MQTT认证失败原因。

## 凭证存储约定

- `/usr/device_secret.json`仍提供`productKey`、`deviceName`、`deviceSecret`三个顶层字段，供旧格式读取。新增版本、代次、序列化记录体和CRC32，校验内容同时约束顶层身份。
- `.bak`保存完整副本；`.tmp`是共用暂存。每份最多4096字节，三个文件峰值12 KiB。CRC用于检测损坏，不是加密。
- 每条记录包含ProductKey、DeviceName和DeviceSecret。同一身份明确更新过的旧密钥也保留；匹配身份时选择最新保留值。普通认证错误不会轮换、删除或自动尝试历史密钥。
- 写入前合并有效记录；只有其他副本仍覆盖全部历史记录时才允许重用一个文件。读回验证成功后才更新其余副本。无法安全合并的异常布局拒绝写入，保留文件等待人工处理。
- 同一凭证和当前身份未变化、双份快照完整时不写盘。进程内读写共用锁，防止云连接和迁移丢失对方的更新。
- 主/备/临时文件及旧目录中的有效凭证、直接配置凭证和迁移快照会合并导入。档案满或空间不足时保留已有记录，阻止新增注册或身份切换；已知身份仍可连接。
- 任一副本读取失败时，可使用其他可读副本中匹配的密钥连接，但不覆盖暂时读不到的文件。若可读副本里没有目标身份，不能据此确认密钥缺失，必须暂停新注册；损坏副本同样不能作为身份不存在的依据。
- 注册前按最长128字符及最坏JSON转义预留容量，实际可保留身份数取决于身份和密钥长度，不承诺固定条数。
- 仅在内存取得、尚未成功写入任何副本时遭遇断电，软件无法保证保留该密钥；因此保存成功前禁止用它激活设备。所有副本同时损坏也需要人工恢复，不会自动删除文件再注册。

## 其他审查发现：本次保留现有行为

### 连接安全模式与传输配置不一致

`collector_cloud.device_auth()`声明`securemode=2`，普通连接和迁移探测却使用`ssl=False`，默认1883端口。阿里云将模式2定义为TLS、模式3定义为TCP。因此存在确定的配置不一致；它是否触发当前实例拒绝，需要独立的实机验证，不能当成本次已证明的首因。本次按既定范围保留协议和端口，后续应统一验证普通登录及迁移探测的连接模式。[阿里云MQTT连接参数](https://help.aliyun.com/zh/iot/user-guide/establish-mqtt-connections-over-tcp)

### 旧MQTT错误回调可能关闭新连接

`CloudClient._mqtt_error()`没有客户端实例或代次检查；每个客户端都注册同一个绑定方法。主机复现中，将当前连接切换到第2代后调用旧回调，新的客户端被关闭，`connected`变为False。监听线程已有代次防护，但错误回调没有。是否由实机SDK延迟触发该回调尚未确认；这是需要后续修复的重连竞态。4.1.5中的凭证保留逻辑可以避免它进一步引发密钥丢失。

OTA回滚路径在文件恢复失败时保留备份/待恢复标记，没有发现与本次相同的“恢复失败仍删除唯一凭证”路径。OTA和迁移期间主动丢弃业务队列是项目已有约定。审查和故障注入不等于所有硬件、固件和掉电时序均已验证。

## 制品与空间验证

发布目录：`dist/collector_app_4.1.5`，基线4.1.4，模块名`collector_app`。只更新云连接、配置、迁移三个旧白名单内模块，不含设备配置、阿里云身份密钥或迁移命令。已比对本地私有配置中的密钥，确认未出现在制品中。

构建使用`--compact`：压缩缩进和注释，字符串内容、AST和源码行号保持一致。仓库源文件保持可读。清单记录制品及原始源码的长度和MD5；旧版回滚预算按未压缩大小估算，已核对基线三个文件均未超过预算。

| 项目 | 占用 |
| --- | ---: |
| 三个新文件按4 KiB对齐 | 72 KiB |
| 暂存目录计入后 | 80 KiB |
| 旧版备份预算，含目录 | 96 KiB |
| updater预算 + OTA安全余量 | 20 + 16 KiB |
| OTA总需求 | **212 KiB / 217,088字节** |
| OTA物理预留 | 256 KiB |
| 部署后全部应用文件，含不变的main.py和其他模块 | 240 KiB |
| 常驻运行文件、凭证双份副本、目录与日志预算 | 64 KiB |
| 常驻运行 + OTA预留合计 | **560 KiB** |
| 序号/设置/凭证临时文件同时存在时 | **572 KiB** |
| 分区总容量 | 576 KiB |

正常布局剩余16 KiB；上述临时文件同时存在时剩余4 KiB。空间模型采用RAM-only队列，并包含`system_config.json`、设备配置、健康标记、迁移完成标记以及`/data`、`/log`目录。旧`/usr/config`目录、无关文件、其他固件生成文件或残留OTA文件会额外占用空间；该估算不能替代实机`statvfs`。程序不会为腾空间自动删除凭证。完整未压缩源码不满足本版预留余量要求，576 KiB设备应使用本次压缩制品。

## 测试和实机边界

主机完整测试：**源码和三模块OTA压缩制品各143项通过**。制品验证先从发布包加载三个模块，再执行完整测试集。覆盖每次凭证写入前/半写入时掉电、唯一有效临时文件、分散的旧格式凭证、更新副本不可读且旧备份仍可读、短写、flush失败、精简文件API、并发保存、容量耗尽、迁移故障、日志脱敏和OTA空间预算。历史4.1.0空间测试改为使用保留的4.1.0制品，避免把当前源码的大小错误套入旧版限制。

主机不连接生产MQTT，未在BW-XC-200-002上刷写或修改阿里云状态。单台设备验收见 [4.1.5单台验收](4.1.5单台验收.md)。发生启动恢复错误时，现有启动器会在有待确认OTA时执行回滚；普通启动需要存储恢复后再次重启，不能把这个行为解释为无限自动重启。
