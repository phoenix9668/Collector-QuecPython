# Collector 4.1.0 EC600M 部署、OTA与身份迁移验收

## 1. 发布前准备

1. 在阿里云产品中导入 `doc/model.zip`。确认原有属性及 `collar_information:SignsData` 未改变，并新增：
   - `product_information:AppVersion`
   - `debugLog`事件
   - `runtimeLog`事件
   - `runtimeLog.metricValue`数值字段（阿里云保留词 `value` 不可作为标识符）
   - 可写布尔属性 `product_information:UartSampleLog`，默认关闭
2. `SendCommand`必须保持可写，但其描述应注明“兼容保留、无业务动作”。
3. 从 `src/device.example.json`生成每台设备的 `/usr/device.json`。阿里云DeviceSecret/ProductSecret不得提交到Git或写入日志；一型一密产生的DeviceSecret由程序缓存到 `/usr/device_secret.json`。QuecLocator沿用原代码内置参数，无需设备配置。
4. 首次烧录包括：`main.py`、所有 `collector_*.py`和设备配置文件。
5. QPYcom手动验证可执行 `example.exec('/usr/main.py')`；启动器会显式设置 `/usr` 为工作目录和模块搜索路径。

## 2. 4.1.0 OTA发布

576 KiB分区无法同时容纳4.0.13到4.1.0全部变化文件、旧版回滚副本及app_fota暂存，所以必须按顺序安装两个正式包，不能合并上传：
 
```powershell
python tools/build_ota_package.py --base-version 4.0.13 --target-version 4.0.15 --include collector_app.py --include collector_cloud.py --include collector_config.py --include collector_ota.py --output dist/collector_app_4.0.15
python tools/build_ota_package.py --base-version 4.0.15 --target-version 4.1.0 --include collector_config.py --include collector_migration.py --include collector_queue.py --output dist/collector_app_4.1.0
```

已生成目录：

- `dist/collector_app_4.0.15/`：4.0.13桥接包，所需空间286,720字节。
- `dist/collector_app_4.1.0/`：4.0.15到4.1.0能力包，所需空间200,704字节。

- 多文件升级：上传对应目录中 `manifest.json` 列出的全部 `.bin`，模块名设为 `collector_app`，版本严格使用清单版本；`aliyun_custom_info.txt`原样粘贴到“推送给设备的自定义信息”。
- 旧版单文件升级：上传 `main.py.bin`，下载协议选择MQTT；扩展信息声明 `target=/usr/main.py`、`packageType=single_file`。该路径只更新稳定启动器，设备必须已存在同版本 `collector_*.py`；不能单独用于把3.x单体程序迁移到4.x。
- 文件URL只允许配置中的阿里云主机。EC600M下载时将阿里云HTTPS URL规范化为HTTP，并强制校验文件大小和MD5。
- `aliyun_custom_info.txt`不要再增加 `_package_udi` 外层。
- OTA云端进度最快每3秒上报一次；USB立即输出阶段日志。下载接口没有字节级回调，因此10%到85%表示下载开始和完成，不伪造中间百分比。
- 4.0.13执行桥接升级时仍运行旧OTA代码，因此该步骤仍要求原有60秒UART静默维护窗口。4.0.15启动后，4.1.0能力包使用25%低占用门限，不再要求UART静默。

普通完整OTA仍只在Flash和RAM积压为零且连续60秒无新体征帧时执行。4.1.0能力包及后续单设备身份迁移包是受限的小包：队列总占用不超过25%即可下载，Flash队列始终保持挂载，UART采集不暂停。

## 3. 生成并下发4.1.1单设备迁移包

1. 目标产品先导入当前 `doc/model.zip`、启用一型一密预注册，并创建尚未激活的目标DeviceName。
2. 从 `src/device_migration.example.json` 复制出仓库根目录的 `device_migration.json`，填写唯一migrationId、旧ProductKey/DeviceName、目标ProductKey/DeviceName、目标MQTT实例地址及ProductSecret。不得填写DeviceSecret。
3. 生成私有包：

```powershell
python tools/build_ota_package.py --base-version 4.1.0 --target-version 4.1.1 --migration-config device_migration.json --output private_dist/collector_app_4.1.1_DEVICE_NAME
```

构建器拒绝占位符、非1883端口、DeviceSecret模式及 `private_dist/` 以外的输出。`private_dist/` 和根目录 `device_migration.json` 已加入Git忽略；包内包含明文ProductSecret，只能定向目标单台设备，迁移结束后应从阿里云删除升级包并关闭动态注册或轮换ProductSecret。

阿里云创建整包升级，模块名 `collector_app`、版本 `4.1.1`，上传 `collector_config.py.bin` 和 `device_migration.json.bin`，粘贴同目录 `aliyun_custom_info.txt`，只选择配置中source身份对应的单台设备。

设备依次执行并打印 `[MIGRATION]`：目标TLS预注册、目标MQTT/runtimeLog探测、等待队列低于25%、记录cutoverSeq、最多300秒排空旧前缀、写入目标身份并重启。水位线后的数据临时直接写入Flash且不发送；迁移前检查会按最近1分钟/5分钟最大到包速率确认75%安全水位前至少还能容纳 `max(64, rate×180×1.5)` 帧。重启后目标runtimeLog必须返回相同ID且code=200，并连续稳定120秒；成功后释放冻结数据。180秒超时、总队列或迁移Flash占用达到75%会恢复旧配置和旧密钥并重启。

如果目标动态注册已经成功，但随后因目标模型、事件回复或网络配置错误导致预检失败，设备会删除迁移暂存密钥而保留旧身份。重新下发前应在阿里云重置该目标设备或创建新的未激活DeviceName，并使用新的migrationId，避免依赖平台重复返回同一DeviceSecret。

迁移状态由 `/usr/.migration_state.0` 和 `.1` 双份CRC记录保护。最终目标ProductSecret写入 `/usr/device.json`，动态注册得到的DeviceSecret写入 `/usr/device_secret.json`；日志不会打印两类密钥。旧阿里云设备不会自动删除，确认目标设备在线和补传结束后再人工禁用。

## 4. OTA空间验收

实机 `/usr` 总容量约576 KiB；`/bak` 是只读的出厂恢复分区，不作为应用OTA或体征队列空间。正常运行按下列方式分配；所有数值均由运行时再次按 `statvfs` 实测，空间不足时只缩小或禁用Flash队列，不覆盖旧数据。

| 用途 | 配额/规则 |
| --- | --- |
| OTA物理预留 `/usr/.ota_space.reserve` | 256 KiB |
| SignsData Flash循环队列 | 动态分配，上限96 KiB；当前布局通常约80–88 KiB |
| 本地严重日志 | 两个轮转文件合计最多16 KiB |
| 队列元数据、序号和动态密钥缓存增长 | 预留20 KiB |
| 身份迁移命令、双状态和完成标记 | 预留20 KiB |
| 文件系统安全余量 | 至少16 KiB |
| 完整应用OTA包 | 4 KiB/文件、8 KiB/目录对齐后不超过176 KiB |

4.0.15桥接包所需总空间286,720字节，低于当前实机约356,352字节可回收空间，但仍应先排空体征队列并清理无关文件。4.1.0能力包需要200,704字节。4.1.1私有迁移包通常只含两个小文件，最终以其manifest和设备实时复核为准。

启动后检查：

- `/usr/.ota_space.reserve`实际大小为262,144字节。
- 60秒统计或启动runtimeLog中的 `flash_frames` 大于0，且队列数据文件不超过96 KiB；约80–88 KiB对应约353–388个Flash体征帧。
- 若无法完整创建预留文件，日志出现 `OTA_RESERVE`错误，Flash队列禁用，但RAM采集仍工作。
- 对照目标包 `manifest.json`，确认 `selfUpdateRequiredBytes` 不超过实机OTA前可回收后的空闲空间。
- 普通完整OTA成功重启后的回滚观察期会暂时占用旧版副本；在90秒健康确认、删除备份并重建预留和Flash队列前，必须继续保持体征源停止发送。4.1.0能力包和4.1.1迁移命令包会在设置更新标志前等待队列瞬时排空；支持新队列的版本随后原子开启Flash直写覆盖重启间隙，不要求UART持续60秒静默。

测试步骤：

1. 使Flash队列接近容量上限，确认预留文件大小保持不变。
2. 断网持续发送体征包，确认Flash深度增长且无覆盖旧数据。
3. 恢复网络并等待积压归零，停止体征源后至少等待60秒，再下发OTA。
4. 校验错误MD5、非法目标路径或空间不足时设备拒绝升级，原应用和未确认体征数据保留。
5. 正常升级后继续保持体征源停止，观察120秒回滚截止窗口；应用稳定运行90秒后写入健康标记、删除备份并重建运行存储。模拟应用启动失败或持续卡死，确认稳定启动器在120秒截止时恢复备份并重启。

## 5. UART满负载验收

UART2参数固定为 `115200 8N1`。线路理论最大约11,520字节/秒，即约55.9个206字节包/秒。

1. 串口发生器连续发送10分钟有效B0包，包含随机粘包、拆包及连续无间隔发送。
2. 同时穿插9字节B2包、`##...##`状态包和少量噪声。
3. 在线状态检查60秒统计日志：`rx_overflow=0`、`rejected=0`，完整帧数与发生器发送数相等。
4. 断开蜂窝网络，在设备公布的RAM+Flash容量内继续发送；重启一次并恢复网络。当前空间规划的Flash上限约423帧、加512帧RAM队列后，满线速理论缓存时间上限约16.7秒；实际以启动公布容量为准。
5. 等待积压清空，核对接收、阿里云成功确认和服务端去重后的数量及顺序。
6. 超过声明容量时必须出现 `QUEUE_FULL`/`DATA_LOSS`严重日志和累计计数，禁止静默覆盖旧包。

## 6. 云连接与身份迁移验收

- 分别验证直接DeviceSecret认证和ProductSecret动态注册；动态注册成功后应生成DeviceSecret缓存。
- 关闭网络再恢复，MQTT按指数退避自动重连，不应因普通断网立即复位模组。
- 丢弃一条属性上报回复，确认设备15秒后使用完全相同的消息ID和负载重发；三次失败后重建连接，数据仍留在队列。
- 乱序返回成功回复，只有连续已确认的队首记录会释放。
- 下发 `SendCommand`，确认云端收到成功回复和runtimeLog，但UART线上没有命令数据。
- 阿里云事件管理中确认 `runtimeLog` 和 `debugLog` 均有数据；60秒统计中的 `event=在途/成功/拒绝/超时/未匹配/重试/返回码` 可用于排障。
- 下发 `UartSampleLog=1` 后，每60秒最多出现一条最多48字节的 `RX_SAMPLE`；重启后设置仍保持。下发0后原始采样停止，但telemetry、解析错误和溢出日志继续输出。
- 检查历史SignsData字符串仍为前导空格、小写、非补零十六进制格式，服务端无需修改解析逻辑。
- 迁移时持续输入多个子设备的数据，确认不会等待60秒UART静默；旧产品只收到 `seq <= cutoverSeq`，目标产品确认成功后收到其后的数据。
- 分别模拟目标密钥错误、runtimeLog拒绝、旧前缀300秒未清空、确认期断网和队列达到75%，确认恢复旧身份且冻结数据仍由旧产品续传。

## 7. 主机回归

执行：

```powershell
python -m unittest discover -s tests -v
python -m compileall -q src tests tools
```

回归覆盖10万连续体征包、随机粘包拆包、Flash重启恢复、乱序ACK、相同ID重试、OTA路径/CRC/空间规则、序号水位线、迁移双状态恢复及物模型压缩包解析。
