# Collector 4.0.4 EC600M 部署与验收

## 1. 发布前准备

1. 在阿里云产品中导入 `doc/model.zip`。确认原有属性及 `collar_information:SignsData` 未改变，并新增：
   - `product_information:AppVersion`
   - `debugLog`事件
   - `runtimeLog`事件
   - `runtimeLog.metricValue`数值字段（阿里云保留词 `value` 不可作为标识符）
2. `SendCommand`必须保持可写，但其描述应注明“兼容保留、无业务动作”。
3. 从 `src/device.example.json`生成每台设备的 `/usr/device.json`。阿里云DeviceSecret/ProductSecret不得提交到Git或写入日志；一型一密产生的DeviceSecret由程序缓存到 `/usr/device_secret.json`。QuecLocator沿用原代码内置参数，无需设备配置。
4. 首次烧录包括：`main.py`、所有 `collector_*.py`和设备配置文件。
5. QPYcom手动验证可执行 `example.exec('/usr/main.py')`；启动器会显式设置 `/usr` 为工作目录和模块搜索路径。

## 2. OTA发布

运行：
 
```powershell
python tools/build_ota_package.py
```

输出目录为 `dist/collector_app_4.0.4/`：

- 多文件升级：上传清单中所有 `collector_*.py.bin`，模块名设为 `collector_app`，版本设为目标应用版本；`manifest.json`中的 `_package_udi`原样作为扩展信息文件映射。
- 旧版单文件升级：上传 `main.py.bin`，下载协议选择MQTT；扩展信息声明 `target=/usr/main.py`、`packageType=single_file`。该路径只更新稳定启动器，设备必须已存在同版本 `collector_*.py`；不能单独用于把3.x单体程序迁移到4.x。
- 文件URL只允许配置中的阿里云主机。EC600M下载时将阿里云HTTPS URL规范化为HTTP，并强制校验文件大小和MD5。
- OTA进度最快每3秒上报一次；升级重连后立即上报 `collector_app`版本。

设备仅在Flash和RAM体征积压都为零、且连续60秒未接收新的完整体征帧时接受实际升级。否则命令保留在队列等待，UART采集不暂停。开始升级后会临时删除空的Flash队列文件和持久日志；下载期间若又收到体征帧，设备会在设置升级标志前取消升级，恢复OTA预留和Flash队列。

## 3. OTA空间验收

实机 `/usr` 总容量约576 KiB；截图中的4.0.3在未建立旧版超大预留时空闲约396 KiB，4.0.4代码对齐占用增加4 KiB，预计基线空闲约392 KiB。`/bak` 是只读的出厂恢复分区，不作为应用OTA或体征队列空间。正常运行按下列方式分配；所有数值均由运行时再次按 `statvfs` 实测，空间不足时只缩小或禁用Flash队列，不覆盖旧数据。

| 用途 | 配额/规则 |
| --- | --- |
| OTA物理预留 `/usr/.ota_space.reserve` | 256 KiB |
| SignsData Flash循环队列 | 动态分配，上限96 KiB；当前布局通常约80–88 KiB |
| 本地严重日志 | 两个轮转文件合计最多16 KiB |
| 队列元数据、序号和动态密钥缓存增长 | 预留20 KiB |
| 文件系统安全余量 | 至少16 KiB |
| 完整应用OTA包 | 4 KiB/文件、8 KiB/目录对齐后不超过176 KiB |

当前4.0.4完整包的对齐占用为172,032字节。按“新包172,032 + 旧版回滚副本172,032 + app_fota约20 KiB + 安全余量16 KiB”估算，完整自升级需要380,928字节（约372 KiB）。OTA开始前，程序会回收空的Flash队列与日志并释放256 KiB预留，实机预计约392 KiB以上的可回收空间可覆盖该需求；设备仍会用实际文件大小再次预检，空间不够则拒绝升级。

启动后检查：

- `/usr/.ota_space.reserve`实际大小为262,144字节。
- 60秒统计或启动runtimeLog中的 `flash_frames` 大于0，且队列数据文件不超过96 KiB；约80–88 KiB对应约353–388个Flash体征帧。
- 若无法完整创建预留文件，日志出现 `OTA_RESERVE`错误，Flash队列禁用，但RAM采集仍工作。
- `dist/collector_app_4.0.4/manifest.json` 的 `alignedBytes` 不超过180,224，`selfUpdateRequiredBytes` 不超过实机OTA前可回收后的空闲空间。
- OTA成功重启后的回滚观察期会暂时占用旧版副本；在90秒健康确认、删除备份并重建预留和Flash队列前，必须继续保持体征源停止发送。

测试步骤：

1. 使Flash队列接近容量上限，确认预留文件大小保持不变。
2. 断网持续发送体征包，确认Flash深度增长且无覆盖旧数据。
3. 恢复网络并等待积压归零，停止体征源后至少等待60秒，再下发OTA。
4. 校验错误MD5、非法目标路径或空间不足时设备拒绝升级，原应用和未确认体征数据保留。
5. 正常升级后继续保持体征源停止，观察120秒回滚截止窗口；应用稳定运行90秒后写入健康标记、删除备份并重建运行存储。模拟应用启动失败或持续卡死，确认稳定启动器在120秒截止时恢复备份并重启。

## 4. UART满负载验收

UART2参数固定为 `115200 8N1`。线路理论最大约11,520字节/秒，即约55.9个206字节包/秒。

1. 串口发生器连续发送10分钟有效B0包，包含随机粘包、拆包及连续无间隔发送。
2. 同时穿插9字节B2包、`##...##`状态包和少量噪声。
3. 在线状态检查60秒统计日志：`rx_overflow=0`、`rejected=0`，完整帧数与发生器发送数相等。
4. 断开蜂窝网络，在设备公布的RAM+Flash容量内继续发送；重启一次并恢复网络。当前空间规划的Flash上限约423帧、加512帧RAM队列后，满线速理论缓存时间上限约16.7秒；实际以启动公布容量为准。
5. 等待积压清空，核对接收、阿里云成功确认和服务端去重后的数量及顺序。
6. 超过声明容量时必须出现 `QUEUE_FULL`/`DATA_LOSS`严重日志和累计计数，禁止静默覆盖旧包。

## 5. 云连接与兼容验收

- 分别验证直接DeviceSecret认证和ProductSecret动态注册；动态注册成功后应生成DeviceSecret缓存。
- 关闭网络再恢复，MQTT按指数退避自动重连，不应因普通断网立即复位模组。
- 丢弃一条属性上报回复，确认设备15秒后使用完全相同的消息ID和负载重发；三次失败后重建连接，数据仍留在队列。
- 乱序返回成功回复，只有连续已确认的队首记录会释放。
- 下发 `SendCommand`，确认云端收到成功回复和runtimeLog，但UART线上没有命令数据。
- 检查历史SignsData字符串仍为前导空格、小写、非补零十六进制格式，服务端无需修改解析逻辑。

## 6. 主机回归

执行：

```powershell
python -m unittest discover -s tests -v
python -m compileall -q src tests tools
```

回归覆盖10万连续体征包、随机粘包拆包、Flash重启恢复、乱序ACK、相同ID重试、OTA路径/CRC/空间规则及物模型压缩包解析。
