## 3. 凭证持久化检查

正常连接日志应出现`credential=cache`；直接配置DeviceSecret的设备显示`credential=config`。升级后第一次连接会将旧格式缓存升级成带校验和历史记录的双份快照。

如需在QPYcom REPL检查，按行执行以下只读命令。先确保REPL可接收命令；若为检查停止了应用，完成后重启设备恢复业务。

```python
import sys
sys.path.insert(0, "/usr")
from collector_config import PROJECT_VERSION, load_device_config, load_cached_device_secret
c = load_device_config()
print("version:", PROJECT_VERSION)
print("identity:", c.product_key, c.device_name)
print("credential_present:", bool(c.device_secret or load_cached_device_secret(c)))
import uos
print("cache_bytes:", uos.stat("/usr/device_secret.json")[6])
print("backup_bytes:", uos.stat("/usr/device_secret.json.bak")[6])
print("ota_reserve_bytes:", uos.stat("/usr/.ota_space.reserve")[6])

```

期望：版本4.1.5，身份不变，`credential_present=True`，缓存与备份各不超过4096字节，健康确认后的预留文件为262144字节。正常写入完成后通常没有`.tmp`；掉电留下的有效`.tmp`可供恢复。

576 KiB分区使用本版制品和标准文件布局时，正常常驻约560 KiB，留16 KiB空闲；临时写盘可使用其中12 KiB。其他历史目录和无关文件会改变结果。若空间不足，保留全部凭证文件，先核对实际目录和占用；不要通过删除凭证腾空间。`flash_frames=0`及`SPOOL_DISABLED`允许出现，此时使用RAM队列。

## 4. 断网、重连和重启

1. 在可控测试环境短暂中断网络，然后恢复。观察设备重新上线和业务上报恢复。现有退避最长300秒，因此恢复网络后可能需要等待约5分钟加网络建立时间。
2. 若需要现场验证“三次连接失败”，让4G保持入网、临时阻断MQTT连接，以日志出现至少4次`CONNECT`失败为判据。恢复后应继续显示`credential=cache`，不出现`AUTH_REFRESH`。主机测试已分别注入超时、认证码4和订阅失败。
3. 在设备正常连接、凭证备份已生成后重启。确认仍使用同一身份、版本4.1.5、凭证来源为cache或config，业务恢复。
4. 复核两份凭证文件仍存在、`credential_present=True`。无需输出或对外发送实际DeviceSecret。

通过条件：升级和90秒健康确认完成；身份保持不变；断网后恢复；重启后复用已保存凭证；数据上报正常；预留文件恢复；日志无持续凭证读写错误。

## 异常处理

- `credential snapshot corrupt`、`credential read failed`：程序保留文件并禁止因“读不到”而重新注册。检查备份、临时文件和存储故障，恢复可读副本后再重启。
- `credential archive full`、`credential disk space insufficient`：已有身份仍可使用已知密钥；新注册或迁移被阻止，不自动淘汰历史凭证。
- `RESTORE_WRITE`、`ROLLBACK_WRITE`：迁移命令和恢复记录仍保留，运行中的迁移工作线程会重试保存。不要删除`.migration_state.*`。
- `boot identity recovery failed`：启动阶段不再使用部分恢复的身份连云。待确认OTA由原启动器处理回滚；普通启动须修复存储后再重启。
